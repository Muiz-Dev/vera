# Overview

The Application Engine is responsible for managing every application registered on the Vera platform.

An Application represents any software that integrates with Vera Identity, including:

* Web Applications
* Mobile Applications
* Desktop Applications
* Backend APIs
* Microservices
* Internal Enterprise Systems
* IoT Devices
* CLI Applications

The Application Engine serves as the central registry for all applications and provides a consistent identity for each application across the Vera ecosystem.

Every OAuth Client, API Key, Webhook, Deployment, Secret, Environment, and Analytics record ultimately belongs to an Application.

---

# Vision

Every software product integrated with Vera should be represented by a secure, uniquely identifiable Application.

Applications should remain portable across environments while maintaining complete auditability and ownership history.

---

# Core Principles

## Every Application Has an Owner

An application belongs to either

* Developer
* Organization

Never both simultaneously.

---

## Immutable Identity

Each application receives one permanent identifier.

```text
Application

↓

app_01KABCXYZ123456789
```

---

## Environment Independent

Applications are independent from environments.

One application can have multiple environments.

Example

```text
Application

↓

Development

↓

Staging

↓

Production
```

---

## Provider Agnostic

Applications should not contain authentication logic.

Authentication belongs to dedicated engines.

---

## Extensible

Applications should support future platform capabilities without schema redesign.

---

# Architecture Decision Record (ADR-007)

**Decision:** Applications are treated as first-class platform resources with immutable identities independent of deployments or environments.

**Reason:** Separating applications from deployments and environments allows Vera to manage application identity consistently while supporting multiple deployment strategies, cloud providers, and runtime environments.

**Consequences:**

* Every application has one permanent identity.
* Deployments and environments remain independent resources.
* Ownership is centralized.
* Future runtime technologies can be introduced without changing the application model.

---

# Design Goals

The Application Engine provides the foundation for application management across Vera by acting as the authoritative registry for every integrated software system.

It establishes a secure, scalable, and extensible model for application identity, ownership, configuration, and lifecycle management while serving as the integration point for authentication, deployments, analytics, billing, environments, and every other platform service that interacts with an application.
