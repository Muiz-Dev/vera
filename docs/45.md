# Overview

The Role Engine defines **who a user is allowed to be** within Vera.

A Role is a named collection of responsibilities and permissions assigned to a User, Developer, Team Member, Organization Member, or Service Account.

The Role Engine works closely with the Authorization Engine but serves a different purpose.

* **Role Engine** defines *who someone is*.
* **Authorization Engine** determines *what someone can do*.

This separation allows Vera to support flexible access control while keeping authorization logic simple, reusable, and maintainable.

# Core Principles

## Roles Are Reusable

A role should be reusable across multiple users.

Example

```text id="role01"
Administrator

↓

25 Users
```

---

## Roles Are Independent

Roles should not contain user-specific information.

A role describes capabilities, not identities.

---

## Roles Reference Permissions

Roles should reference Permissions instead of embedding authorization logic.

```text id="role02"
Role

↓

Permissions

↓

Resources
```

---

## Roles Are Scoped

Roles may exist within different scopes.

Supported scopes

* Platform
* Organization
* Team
* Application

---

## Extensible

Organizations should be able to define custom roles without affecting system roles.

---

# Responsibilities

The Role Engine is responsible for

* Creating roles
* Updating roles
* Deleting roles
* Assigning roles
* Removing roles
* Managing role templates
* Managing role metadata
* Recording role history

The Role Engine is NOT responsible for

* Permission evaluation
* Authentication
* Session validation
* Billing

# Architecture Decision Record (ADR-005)

**Decision:** Roles represent identity responsibilities and are separate from permission evaluation.

**Reason:** Separating role management from authorization policies keeps Vera modular, simplifies access control, enables custom organizational roles, and allows future authorization models without redesigning role storage.

**Consequences:**

* Roles remain reusable and portable.
* Permissions evolve independently.
* Organizations can define custom roles safely.
* Authorization logic remains centralized in the Authorization Engine.

---

# Design Goals

The Role Engine establishes Vera's role management foundation by providing a flexible, scalable, and secure RBAC model.

It enables organizations to define responsibilities consistently across users, teams, applications, and resources while maintaining strong auditability, preventing privilege escalation, and integrating seamlessly with the Authorization Engine for fine-grained access control.
