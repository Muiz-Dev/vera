# Overview

The OAuth Engine provides standards-based authorization for applications integrated with the Vera platform.

It enables third-party applications, first-party applications, mobile apps, desktop software, backend services, and IoT devices to securely obtain limited access to protected resources without exposing user credentials.

The OAuth Engine is built around **OAuth 2.1** and is designed to support future extensions including **OpenID Connect (OIDC)**, **PKCE**, **Device Authorization Grant**, **JWT Access Tokens**, and enterprise federation.

Rather than authenticating users directly, the OAuth Engine issues and manages authorization grants, access tokens, refresh tokens, scopes, client registrations, and user consent.

# Core Principles

## Standards First

The OAuth Engine follows open standards.

Primary standards include

* OAuth 2.1
* RFC 7636 (PKCE)
* RFC 7009 (Token Revocation)
* RFC 7662 (Token Introspection)
* RFC 8252 (Native Apps)
* OpenID Connect (Future)

---

## Applications Authenticate

OAuth Clients represent Applications.

Users never authenticate directly against OAuth Clients.


## Least Privilege

Applications request only the scopes they require.

Example

```text id="oauth02"

email.read

users.write
```

---

## Consent Required

Users must approve access before tokens are issued.

---

## Token Separation

Access Tokens and Refresh Tokens serve different purposes.

Access Tokens

* Short-lived
* Resource access

Refresh Tokens

* Long-lived
* Obtain new Access Tokens

* Client registration

* Token issuance
* Refresh tokens
* Consent
* Scope validation
* Revocation

The OAuth Engine is NOT responsible for

* User passwords
* MFA
* Billing

* API authorization

# Architecture Decision Record (ADR-010)

**Decision:** Vera adopts OAuth 2.1 as its primary authorization framework with mandatory PKCE for public clients.

**Reason:** OAuth 2.1 consolidates current security best practices by removing insecure legacy flows and encouraging PKCE, refresh token rotation, and secure client authentication, making it suitable for modern web, mobile, desktop, and enterprise applications.

**Consequences:**

* Legacy implicit flows are not supported.
* Public clients must implement PKCE.
* OAuth integrations remain interoperable with industry standards.
* Future OpenID Connect support can be layered on without redesign.

# Design Goals

The OAuth Engine provides Vera's standards-compliant authorization infrastructure by enabling secure delegated access between users, applications, and protected resources.

Its architecture emphasizes interoperability, security, scalability, and developer experience while integrating seamlessly with the Identity, Permission, Authorization, and Application Engines to deliver a modern, enterprise-ready authentication ecosystem.
