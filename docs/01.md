# Vera

> A developer-first identity platform for authentication, authorization, session management, and user identity.

---

# Overview

Vera is an identity platform designed to provide secure, scalable, and developer-friendly authentication infrastructure.

Instead of every application implementing its own authentication system, Vera provides a centralized identity service that applications can integrate through APIs and SDKs.

The long-term goal is to provide an ecosystem similar to modern identity platforms while remaining API-first, extensible, and self-hostable.

---

# Why Vera Exists

Building authentication correctly is difficult.

Every application eventually needs:

* User registration
* User authentication
* Password hashing
* Email verification
* Password reset
* Session management
* Refresh tokens
* Role-based access control
* Multi-factor authentication
* API keys
* OAuth providers
* Audit logs
* Organization management

Most developers rebuild these features repeatedly.

Vera exists to provide these capabilities as a dedicated identity platform.

---

# What Vera Is

Vera is an Identity Platform.

It manages identities, authentication, authorization, applications, sessions, organizations, permissions, and developer integrations.

Applications trust Vera to authenticate users instead of implementing authentication internally.

---

# What Vera Is Not

Vera is not:

* A frontend framework
* A website builder
* A CMS
* A backend framework
* A database
* A replacement for PostgreSQL

It is an identity engine.

---

# Current Phase

Current development phase:

**Phase 1 — Core Engine**

The objective of Phase 1 is to establish the backend foundation before implementing authentication.

This phase focuses on infrastructure rather than features.

Completed components include:

* Express server
* TypeScript project
* Prisma ORM
* PostgreSQL connection
* Database migrations
* Project structure

Authentication features are intentionally postponed until the platform foundation is complete.

# Engineering Principles

Every part of Vera should follow these principles.

## Simplicity

Prefer simple solutions over complex abstractions.

---

## Security

Security is never optional.

Authentication, passwords, sessions, and secrets are treated as first-class concerns.

---

## Consistency

Naming, folder structures, APIs, and database models should remain predictable throughout the project.

---

## Scalability

Design decisions should support future growth without unnecessary complexity during early development.

---

## Developer Experience

Every API should be easy to understand, well documented, and predictable.
