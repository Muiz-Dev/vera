# Overview

The Refresh Token Engine manages the complete lifecycle of Refresh Tokens across the Vera platform.

A Refresh Token is a long-lived credential that enables a client application to obtain new Access Tokens without requiring the user to authenticate again.

Unlike Access Tokens, Refresh Tokens are **never presented to APIs**. They are exchanged only with the Vera Authorization Server.

The Refresh Token Engine provides secure issuance, rotation, validation, revocation, expiration, device binding, session association, and audit capabilities while protecting users from credential theft and replay attacks.

# Core Principles

## Refresh Tokens Are Long-Lived

Refresh Tokens exist longer than Access Tokens.

Recommended lifetimes

| Token         | Recommended Lifetime |
| ------------- | -------------------- |
| Access Token  | 15 Minutes           |
| Refresh Token | 30 Days              |

---

## Never Sent to APIs

Refresh Tokens are exchanged only with the Authorization Server.

They must never be accepted by application APIs.

---

## One-Time Rotation

Every successful refresh operation should issue

* New Access Token
* New Refresh Token

The previous Refresh Token becomes invalid immediately.

---

## Device Bound

Refresh Tokens should be associated with

* Device
* Session
* Client Application
* User

This improves compromise detection.

---

## Secure Storage

Refresh Tokens must be

* Hashed
* Encrypted in transit
* Protected against replay attacks

---

The Refresh Token Engine is responsible for

# Architecture Decision Record (ADR-013)

**Decision:** Vera uses rotating Refresh Tokens with single-use semantics and token family tracking.

**Reason:** Rotating Refresh Tokens significantly reduce the impact of credential theft, enable replay detection, improve session security, and align with modern OAuth 2.1 security recommendations.

**Consequences:**

* Every refresh operation invalidates the previous Refresh Token.
* Replay attacks can be detected reliably.
* Compromised sessions can be terminated immediately.
* Long-lived sessions remain secure without requiring repeated user logins.

---

# Design Goals

The Refresh Token Engine provides Vera's long-lived credential infrastructure by securely maintaining authenticated user sessions while minimizing security risks through automatic rotation, replay detection, session binding, and comprehensive auditing.

Its architecture enables seamless user experiences across web, mobile, desktop, and enterprise applications while integrating tightly with the Token Engine, Authentication Engine, Session Engine, Device Engine, OAuth Engine, and Access Token Engine to provide a secure, scalable, and resilient authentication ecosystem.
