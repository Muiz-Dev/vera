# 13 — Session Engine

Version: 0.1.0

---

# Overview

The Session Engine is responsible for tracking authenticated identities across devices.

Authentication proves identity.

The Session Engine maintains that authenticated state securely over time.

Every successful login creates a new session.

---

# Goals

The Session Engine should provide:

* Secure session creation
* Session validation
* Session revocation
* Multi-device support
* Session expiration
* Device tracking
* Refresh token management
* Session analytics

---

# Responsibilities

The Session Engine is responsible for:

* Creating sessions
* Validating sessions
* Revoking sessions
* Tracking active devices
* Rotating refresh tokens
* Recording session activity
* Detecting expired sessions

It does not perform authentication or authorization.

# Session Model

Every session represents one authenticated login.

One user may have many active sessions.

Example

```text id="ses02"
Developer

├── Laptop

├── Desktop

├── Phone

└── Tablet
```

Each device maintains its own independent session.

# Session States

A session can exist in one of four states.

```text id="ses04"
Active

Expired

Revoked

Compromised
```

---

# Active Session

Requirements

* Valid access token
* Valid refresh token
* Not expired
* Not revoked

---

# Expired Session

Occurs when:

* Expiration time passes
* Refresh token expires

Expired sessions cannot be reused.

---

# Revoked Session

Revocation occurs when:

* User logs out
* Password changes
* Administrator revokes access
* API explicitly revokes session

Revoked sessions become permanently invalid.

---

# Compromised Session

Future versions may mark sessions as compromised.

Examples

* Suspicious IP changes
* Impossible travel
* Stolen refresh token
* Security alert

Compromised sessions should be revoked immediately.

# Multi-Device Support

Users may remain logged in on multiple devices.

Example

```text id="ses06"
Desktop

Phone

Tablet

Laptop
```

Each session is isolated.

Revoking one session does not affect others.

---

# Refresh Token Rotation

Every refresh operation issues:

* New Access Token
* New Refresh Token

The previous refresh token becomes invalid immediately.

This reduces replay attacks.

---

# Session Expiration

Recommended defaults

Access Token

```text id="ses07"
15 minutes
```

Refresh Token

```text id="ses08"
30 days
```

Inactive sessions should eventually expire automatically.

# Security Rules

Sessions must:

* Use HTTPS
* Rotate refresh tokens
* Store hashed refresh tokens where practical
* Detect revoked sessions
* Prevent replay attacks
* Validate expiration

Session identifiers should be cryptographically secure.

# Design Goals

The Session Engine should provide a secure and reliable way to manage authenticated sessions across multiple devices.

Every session should be individually identifiable, independently revocable, auditable, and resilient against common session-related attacks while maintaining a simple developer experience.
