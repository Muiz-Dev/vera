# 28 — Notification Engine

Version: 0.1.0

---

# Overview

The Notification Engine is responsible for delivering notifications to developers and end users across multiple communication channels.

Unlike the Email Engine, which only sends emails, the Notification Engine acts as a unified communication layer capable of delivering the same notification through different providers.

---

# Goals

The Notification Engine should provide:

* Multi-channel notifications
* Notification templates
* Delivery preferences
* Notification history
* Retry mechanisms
* Scheduling
* Provider abstraction

---

# Responsibilities

The Notification Engine is responsible for:

* Creating notifications
* Selecting delivery channels
* Rendering templates
* Sending notifications
* Tracking delivery
* Recording notification history

It is **not** responsible for authentication or authorization.

---

The Notification Engine determines how it is delivered.

# Security Notifications

The following notifications should always be delivered immediately

* Password Changed
* Email Changed
* MFA Enabled
* MFA Disabled
* New Device Login
* API Key Revoked

These notifications should never be silently discarded.

# Integration

The Notification Engine integrates with

* Email Engine
* Event Engine
* Authentication Engine
* Audit Engine
* Monitoring Engine
* Webhook Engine

Every major system event should be capable of generating one or more notifications through the Notification Engine.

---

# Design Goals

The Notification Engine should provide a centralized, reliable, and extensible communication system for Vera.

Applications should generate notifications without needing to know which delivery channel is used, allowing Vera to support new communication methods without changing application logic.
