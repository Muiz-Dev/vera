# 32 — CLI Engine

Version: 0.1.0

---

# Overview

The CLI (Command Line Interface) Engine provides developers with a fast and consistent way to interact with Vera directly from the terminal.

Instead of performing administrative actions through the dashboard or making raw API requests, developers can use simple CLI commands.

The CLI is intended for local development, automation, CI/CD pipelines, and production administration.

---

# Goals

The CLI Engine should provide:

* Authentication
* Project management
* Environment management
* Application management
* API Key management
* Deployment utilities
* Administrative tools

---

# Responsibilities

The CLI Engine is responsible for:

* Executing CLI commands
* Authenticating users
* Calling the Vera API
* Displaying formatted output
* Managing local configuration
* Supporting automation

It is **not** responsible for business logic.

---

# Design Philosophy

Everything that can be done from the dashboard should also be possible from the CLI.

Example

```bash id="cli01"
vera login
```

```bash id="cli02"

```

```bash id="cli03"

```

# Security

The CLI Engine must

* Store tokens securely
* Validate server certificates
* Support HTTPS only
* Prevent accidental secret exposure
* Require confirmation for destructive actions

# Integration

The CLI Engine integrates with

* Authentication Engine
* Configuration Engine
* SDK Engine
* API Key Engine
* Webhook Engine
* Monitoring Engine

The CLI should consume the same public APIs as external developers, ensuring feature parity with the Vera platform.

---

# Design Goals

The CLI Engine should provide a fast, secure, and automation-friendly interface for interacting with Vera.

Developers should be able to manage applications, organizations, API keys, and deployments entirely from the terminal while maintaining a consistent experience across local development, CI/CD pipelines, and production environments.
