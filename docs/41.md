# Overview

The User Engine is the foundational identity component of the Vera platform.

Every authenticated identity within Vera originates from the User Engine. It is responsible for creating, managing, securing, validating, and maintaining user identities throughout their lifecycle.

Every other engine—including Authentication, Authorization, Sessions, Organizations, Teams, Applications, Billing, Audit, Notifications, MFA, and OAuth—depends directly or indirectly on the User Engine.

The User Engine is designed around a single principle:

> **Every identity has exactly one canonical User record.**

Regardless of how a user signs in (email/password, Google, GitHub, Microsoft, passwordless, SSO, or future providers), there must only ever be one primary user identity.

---

# Objectives

The User Engine exists to provide:

* Centralized identity management
* Secure user lifecycle management
* Unique identity resolution
* Profile management
* Identity verification
* Account state management
* User metadata management
* Cross-engine identity consistency

---

# Vision

The User Engine should become the single source of truth for every identity within Vera.

No service should create or maintain independent user records.

Instead, every service references a User.

---

# Core Principles

The User Engine follows these architectural principles.

## Single Source of Truth

Only one user record exists for each person.

No duplicate identities.

---

## Immutable Identity

A User ID never changes.

Names may change.

Emails may change.

Organizations may change.

The User ID remains permanent.

---

## Separation of Identity

Identity is separate from authentication.

Example

```text
User

↓

Authentication Method

↓

Session

↓

Application Access
```

Removing a login provider does not remove the user.

---

## Provider Agnostic

The User Engine knows nothing about Google, GitHub, Microsoft, Apple, or Passwords.

Those belong to Authentication Providers.

The User only represents the person.

---

## Extensible

Future identity providers should require zero modifications to the User model.

---

# Architecture Decision Record (ADR-001)

**Decision:** Every identity within Vera is represented by exactly one immutable User record.

**Reason:** A single canonical identity eliminates duplication, simplifies authentication provider linking, reduces authorization complexity, and provides a stable reference across all platform services.

**Consequences:**

* Every engine references `user.id`.
* Authentication providers remain independent of user storage.
* Email and usernames become mutable attributes rather than primary identifiers.
* Future authentication methods can be introduced without redesigning the User model.

---

# Design Goals

The User Engine serves as the identity foundation of Vera.

Every authenticated person, regardless of provider or authentication method, is represented by one immutable User record that becomes the trusted source of identity across the entire platform. The engine prioritizes consistency, security, scalability, and extensibility so that future platform capabilities can be built without altering the core identity model.
