# 27 — Webhook Engine

Version: 0.1.0

---

# Overview

The Webhook Engine allows Vera to notify external applications when important events occur.

Instead of applications constantly polling Vera for changes, Vera pushes events to registered webhook endpoints in real time.

Webhooks enable automation and integration with third-party systems.

---

# Goals

The Webhook Engine should provide:

* Event delivery
* Secure webhook signing
* Automatic retries
* Delivery tracking
* Event filtering
* Provider-independent architecture
* Reliable event delivery

---

# Responsibilities

The Webhook Engine is responsible for:

* Registering webhook endpoints
* Publishing webhook events
* Signing payloads
* Delivering HTTP requests
* Retrying failed deliveries
* Recording delivery history

It is **not** responsible for internal application events.

---

# HTTP Method

```text id="webhook08"

```

---

# Response Handling

Successful delivery

```text id="webhook09"
HTTP 200

HTTP 201

HTTP 202

HTTP 204
```

Other responses are treated as delivery failures.

---

# Signing Requests

Every webhook request should include a signature.

Example header

```text id="webhook10"
X-Vera-Signature
```

The signature is generated using the webhook secret.

Recommended algorithm

```text id="webhook11"
HMAC-SHA256
```

---

# Delivery Timeout

Suggested timeout

```text id="webhook12"
10 Seconds
```

Requests exceeding the timeout are treated as failed deliveries.

---

# Security

The Webhook Engine must

* Require HTTPS in production
* Validate endpoint URLs
* Sign every request
* Prevent replay attacks
* Support IP allowlists (future)
* Log delivery failures

# Integration

The Webhook Engine integrates with

* Event Engine
* Audit Engine
* Monitoring Engine
* Logging Engine
* Authentication Engine

All external notifications should originate from the Event Engine and be delivered through the Webhook Engine.

---

# Design Goals

The Webhook Engine should provide secure, reliable, and scalable event delivery to external applications.

Every webhook delivery should be authenticated, traceable, retryable, and resilient against temporary network failures while remaining simple for developers to integrate.
