# 05 — API Specification

Version: 0.1.0

---

# Overview

This document defines the API design principles and endpoint specifications for Vera.

The API is the primary interface between applications and the Vera Identity Platform.

Every endpoint must be:

* Predictable
* Versioned
* Secure
* Consistent
* Well documented

All APIs communicate using JSON.

---

# Base URL

Development

```text
http://localhost:3000/api/v1
```

Production

```text
https://api.vera.dev/v1
```

---

# API Versioning

Every endpoint is versioned.

Example

```text
/api/v1
```

Future versions

```text
/api/v2

/api/v3
```

Breaking changes should never be introduced without creating a new API version.

---

# Content Type

All requests must send

```http
Content-Type: application/json
```

Responses

```http
Content-Type: application/json
```

---

# HTTP Methods

| Method | Purpose           |
| ------ | ----------------- |
| GET    | Retrieve data     |
| POST   | Create resources  |
| PUT    | Replace resources |
| PATCH  | Update resources  |
| DELETE | Remove resources  |

---

# Response Structure

Every successful response follows the same format.

```json
{
    "success": true,
    "message": "Operation completed successfully.",
    "data": {}
}
```

---

# Error Response

Every failed request follows the same structure.

```json
{
    "success": false,
    "message": "Validation failed.",
    "errors": []
}
```

# Developer Endpoints

Phase Two

---

## Register Developer

```http
POST /developers
```

Purpose

Create a new developer account.

### Request

```json
{
    "email": "john@example.com",
    "password": "********"
}
```

### Response

```json
{
    "success": true,
    "message": "Developer created successfully.",
    "data": {
        "id": "...",
        "email": "john@example.com"
    }
}
```

---

## Login Developer

```http
POST /developers/login
```

Purpose

Authenticate a developer.

### Request

```json
{
    "email": "john@example.com",
    "password": "********"
}
```

### Response

```json
{
    "success": true,
    "data": {
        "accessToken": "...",
        "refreshToken": "..."
    }
}
```

---

## Current Developer

```http
GET /developers/me
```

Purpose

Retrieve the currently authenticated developer.

Authentication Required

Yes

# Application Endpoints

Phase Three

---

## Create Application

```http
POST /applications
```

Purpose

Create a new application.

### Request

```json
{
    "name": "Marketplace"
}
```

### Response

```json
{
    "success": true,
    "data": {
        "id": "...",
        "name": "Marketplace",
        "publicKey": "...",
        "secretKey": "..."
    }
}
```

---

## Get Applications

```http
GET /applications
```

Returns every application owned by the authenticated developer.

---

## Get Application

```http
GET /applications/:id
```

Returns one application.

---

## Update Application

```http
PATCH /applications/:id
```

Updates application information.

---

## Delete Application

```http
DELETE /applications/:id
```

Archives an application.

Applications should not be permanently deleted.

# Pagination

List endpoints should support pagination.

Example

```http
GET /users?page=1&limit=20
```

Response

```json
{
    "success": true,
    "data": [],
    "pagination": {
        "page": 1,
        "limit": 20,
        "total": 120,
        "pages": 6
    }
}
```

---

# Authentication

Protected endpoints require

```http
Authorization: Bearer <access-token>
```

Public endpoints do not require authentication.

---

# API Design Rules

* Use nouns instead of verbs.
* Use plural resource names.
* Return JSON only.
* Version every endpoint.
* Never expose internal database identifiers unnecessarily.
* Use consistent response structures.
* Validate every request.
* Return meaningful error messages.
* Keep endpoints RESTful.

---

# API Goals

The Vera API should be:

* Easy to understand
* Easy to integrate
* Predictable
* Secure
* Stable
* Backward compatible whenever possible

Every endpoint should provide a consistent developer experience regardless of the feature being accessed.
