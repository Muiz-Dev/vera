# Overview

The Device Engine is responsible for identifying, registering, tracking, managing, and securing every device that interacts with the Vera platform.

A device represents any physical or virtual endpoint capable of authenticating with Vera, including web browsers, mobile phones, desktop applications, servers, IoT devices, CI/CD runners, and command-line interfaces.

The Device Engine establishes a trusted relationship between identities and devices, allowing Vera to improve security, detect anomalies, simplify authentication, and provide users with visibility into every device that has accessed their account.

Rather than treating every login as identical, Vera understands the context of the device being used and continuously evaluates its trustworthiness.

# Vision

Every device interacting with Vera should have a persistent identity, comprehensive lifecycle management, and a continuously updated trust profile that enables secure authentication without compromising user privacy.

---

# Core Principles

## Every Device Has an Identity

Every recognized device receives a permanent identifier.

```text id="device01"
device_01KABCXYZ987654321
```

The identifier remains constant even as sessions change.

---

## Devices Belong to Identities

A device may be associated with

* User
* Developer
* Organization
* Service Account
* Application

Ownership determines management permissions.

---

## Device Awareness

Authentication decisions should consider device context in addition to user credentials.

Examples include

* First login
* New browser
* Operating system change
* Suspicious hardware change
* Geographic inconsistency

---

## Privacy First

The Device Engine should collect only the information necessary to establish identity and improve security.

Sensitive personal information should never be collected unnecessarily.

---

## Independent Lifecycle

A device remains registered independently of active sessions.

Logging out ends a session but does not automatically delete the device.

---

# Responsibilities

The Device Engine is responsible for

* Device registration
* Device identification
* Metadata collection
* Device inventory
* Activity history
* Device status
* Device removal
* Device synchronization

The Device Engine is NOT responsible for

* User authentication
* Risk scoring
* MFA enforcement
* Session creation
* OAuth authorization

# Validation Rules

* Every device requires an owner.
* Device identifiers are immutable.
* Revoked devices cannot authenticate.
* Device metadata must be validated before storage.
* Duplicate device registrations should be merged when appropriate.

# Architecture Decision Record (ADR-015)

**Decision:** Every endpoint interacting with Vera is represented as a first-class Device entity with its own lifecycle, metadata, and security state.

**Reason:** Separating device identity from user identity enables stronger authentication, improved anomaly detection, better session management, and a significantly enhanced security posture without increasing user friction.

**Consequences:**

* Users gain visibility into every device accessing their accounts.
* Security engines can make context-aware decisions.
* Device compromise can be isolated without affecting the entire account.
* Future trust and risk engines can build upon a persistent device identity model.

---

# Design Goals

The Device Engine provides Vera's device identity infrastructure by maintaining persistent records of every trusted endpoint interacting with the platform.

Its architecture emphasizes security, privacy, scalability, lifecycle management, and interoperability while integrating seamlessly with the Authentication Engine, Session Engine, Refresh Token Engine, Risk Engine, and Device Trust Engine to deliver intelligent, context-aware authentication across the Vera ecosystem.
