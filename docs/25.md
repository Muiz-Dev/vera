# 25 — OAuth Engine

Version: 0.1.0

---

# Overview

The OAuth Engine enables developers to authenticate users using third-party identity providers without requiring users to create new passwords.

Vera acts as the identity broker between applications and external providers.

The OAuth Engine follows OAuth 2.0 and OpenID Connect (OIDC) standards where applicable.

---

# Goals

The OAuth Engine should provide:

* Social login
* OAuth 2.0 support
* OpenID Connect support
* Account linking
* Provider abstraction
* Secure token handling
* Extensible provider architecture

---

# Responsibilities

The OAuth Engine is responsible for:

* Starting OAuth flows
* Exchanging authorization codes
* Verifying identity tokens
* Creating user accounts
* Linking existing accounts
* Managing provider identities

It is **not** responsible for session management.

---

# Token Handling

Vera should never permanently store third-party access tokens unless explicitly required.

Temporary tokens should be encrypted and expire automatically.

---

# Identity Verification

After successful authentication

1. Verify identity token
2. Validate issuer
3. Validate audience
4. Validate expiration
5. Retrieve profile information
6. Create or link account

---

# Email Matching

If the provider returns a verified email

```text id="oauth11"
Existing Email?

↓

Yes

↓

Link Account

↓

No

↓

Create New Account
```

Duplicate accounts should be avoided.

---

# Error Handling

Common errors

* Authorization denied
* Invalid authorization code
* Expired authorization code
* Invalid identity token
* Provider unavailable
* Network timeout

Errors should never expose provider secrets.

---

# Security

The OAuth Engine must

* Validate redirect URIs
* Validate state parameters
* Validate nonce values
* Prevent CSRF attacks
* Verify identity token signatures
* Require HTTPS in production

---

# Redirect URI Validation

Only registered redirect URIs may be used.

Example

```text id="oauth13"
https://example.com/auth/callback
```

Wildcard redirects should not be permitted.

---

# Scopes

Applications request only the scopes they need.

Example

```text id="oauth14"
openid

profile

email
```

The principle of least privilege should always apply.

---

# Design Goals

The OAuth Engine should provide a secure, standards-compliant, and provider-independent authentication system.

Applications should integrate once with Vera while gaining access to multiple identity providers through a consistent API and developer experience.
