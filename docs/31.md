# 31 — SDK Engine

Version: 0.1.0

---

# Overview

The SDK Engine provides official libraries that allow developers to integrate Vera into their applications with minimal effort.

Instead of manually making HTTP requests, developers interact with a native SDK designed for their programming language.

The SDK abstracts authentication, request signing, retries, pagination, and error handling.

---

# Goals

The SDK Engine should provide:

* Official SDKs
* Type-safe APIs
* Automatic authentication
* Request retries
* Error handling
* Pagination support
* Version compatibility

---

# Responsibilities

The SDK Engine is responsible for:

* Communicating with the Vera API
* Managing API authentication
* Serializing requests
* Parsing responses
* Handling retries
* Exposing developer-friendly APIs

It is **not** responsible for business logic.

---

# Design Philosophy

Developers should write as little code as possible.

Example

```ts id="sdk01"
const vera = new Vera({
  apiKey: process.env.VERA_API_KEY,
});

const developer = await vera.developers.me();
```

The SDK should hide transport complexity.

# Retries

Retry temporary failures

Examples

* Network interruption
* HTTP 429
* HTTP 503

Permanent failures should not be retried automatically.

# Design Goals

The SDK Engine should make Vera easy to adopt by providing reliable, type-safe, and well-documented client libraries.

Developers should be able to integrate Vera into their applications with minimal configuration while benefiting from automatic authentication, retries, pagination, and consistent APIs across every supported language.
