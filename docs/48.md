# Overview

The Environment Engine manages isolated runtime environments for every application registered within the Vera platform.

An Environment represents a distinct operational context where an application executes with its own configuration, secrets, domains, API keys, deployments, and security policies.

Typical environments include:

* Development
* Testing
* QA
* Staging
* Production
* Preview
* Sandbox

By isolating environments, Vera ensures that changes made during development or testing cannot affect production systems, while allowing developers to safely deploy, validate, and promote releases.

# Vision

Every Vera application should support multiple isolated environments that share the same application identity while maintaining independent runtime configurations and security boundaries.

---

# Core Principles

## Environment Belongs to an Application

Every environment must reference exactly one Application.

```text id="env01"
Application

↓

Environment
```

---

## Isolation First

No environment should automatically inherit runtime data from another environment.

Development should never impact Production.

---

## Immutable Identity

Each environment receives a permanent identifier.

```text id="env02"
env_01KABCXYZ987654321
```

---

## Independent Configuration

Each environment owns

* Secrets
* Variables
* Domains
* OAuth settings
* API Keys
* Deployments

---

## Extensible

Future runtime capabilities should be supported without redesigning the Environment model.

---

# Responsibilities

The Environment Engine is responsible for

* Environment creation
* Environment updates
* Environment deletion
* Runtime configuration
* Environment metadata
* Domain association
* Variable management
* Environment lifecycle

The Environment Engine is NOT responsible for

* Deployments
* Secret encryption
* Authentication
* Billing
* OAuth

# Architecture Decision Record (ADR-008)

**Decision:** Environments are isolated runtime containers that belong to Applications and maintain independent configuration, variables, and operational settings.

**Reason:** Strong isolation reduces deployment risk, improves operational safety, enables continuous delivery, and supports modern deployment strategies such as staging, preview, canary, and blue/green releases.

**Consequences:**

* Applications maintain one identity across multiple environments.
* Runtime configuration remains isolated.
* Secrets and variables cannot leak across environments.
* Future deployment strategies can be introduced without redesigning the Application model.

---

# Design Goals

The Environment Engine provides the operational foundation for application execution within Vera by delivering isolated runtime environments with independent configuration, security boundaries, deployment targets, and resource management.

Its architecture enables developers to confidently build, test, deploy, and operate applications while ensuring consistency, scalability, security, and seamless integration with deployments, secrets, domains, monitoring, and the broader Vera platform ecosystem.
